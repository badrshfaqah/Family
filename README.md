# نظام إدارة محتوى العوائل والقبائل

نظام CMS عربي خفيف وقابل لإعادة الاستخدام، مخصص لإنشاء موقع رسمي عام لأي عائلة أو قبيلة أو رابطة أو ديوانية، دون أي عضويات عامة أو عرض لبيانات شخصية للأفراد.

> **ملاحظة عن حالة المشروع:** هذا العمل جارٍ على مراحل. النواة، معالج التثبيت، لوحة التحكم، والإضافة الأولى (الصفحات) مبنية ومختبرة فعليًا (تثبيت كامل من المتصفح، تسجيل دخول، تفعيل/تعطيل/إزالة إضافة، إنشاء ونشر محتوى). بقية الإضافات (الأخبار، المناسبات، الرزنامة، الجمعات، جوال العائلة، القائمة البريدية، شجرة النسب، المعرض، الأرشيف، الإعلانات) قيد الإكمال حسب الترتيب المتفق عليه. راجع CHANGELOG.md لمعرفة آخر التحديثات بدقة.

---

## المتطلبات

- استضافة مشتركة عادية (لا حاجة لأي وصول Root أو SSH).
- PHP 8.1 أو أحدث.
- امتدادات PHP: `pdo_mysql`, `mbstring`, `gd`, `fileinfo`, `json`, `session`.
- امتداد اختياري: `zip` (لرفع الإضافات بصيغة ZIP والنسخ الاحتياطي للملفات — النظام يعمل بدونه لكن بإمكانيات أقل).
- قاعدة بيانات MySQL 5.7+ / MariaDB 10.3+.
- لا حاجة إلى Node.js، ولا Composer، ولا Docker، ولا أي وصول Terminal بعد رفع الملفات.

## التثبيت (من المتصفح بالكامل)

1. ارفع جميع ملفات المشروع إلى الاستضافة (عبر مدير الملفات أو FTP)، إما في الجذر الرئيسي للدومين أو داخل أي مجلد فرعي.
2. أنشئ قاعدة بيانات MySQL فارغة ومستخدمًا له صلاحية كاملة عليها من لوحة تحكم الاستضافة.
3. افتح الموقع من المتصفح — سيتم تحويلك تلقائيًا لصفحة `/install/`.
4. اتبع خطوات المعالج: اللغة → فحص المتطلبات → بيانات قاعدة البيانات → بيانات الموقع والمصطلح → حساب المدير → الإنهاء.
5. بعد نجاح التثبيت سيتم إنشاء `config.php` وملف `storage/installed.lock` تلقائيًا، وتحويلك لصفحة دخول لوحة التحكم.

لا حاجة لاستيراد قاعدة بيانات، ولا لتعديل أي ملف يدويًا، ولا لتشغيل أي أمر.

### إعادة التثبيت

لأسباب أمنية، بمجرد نجاح التثبيت يُمنع معالج التثبيت من العمل مرة أخرى تلقائيًا (يتحقق من وجود `storage/installed.lock`). لإعادة التثبيت من الصفر (مثلًا في بيئة تطوير)، احذف يدويًا عبر مدير الملفات:
- `config.php`
- `storage/installed.lock`
- `storage/cache/settings.php` (إن وُجد)

وأعد فتح `/install/` من جديد.

### التركيب داخل مجلد فرعي أو بجانب ووردبريس

النظام يكتشف مساره تلقائيًا من مسار نقطة الدخول الفعلية (`index.php` / `admin/index.php` / `install/index.php`) في كل طلب، ولا يخزن أي رابط مطلق ثابت لموقع التركيب. لذلك:
- يعمل بلا أي تعديل داخل الجذر الرئيسي أو داخل أي مجلد فرعي.
- يمكن تركيبه في مجلد فرعي بجانب تركيب ووردبريس آخر في نفس الاستضافة دون أي تعارض، طالما كل نظام في مجلده الخاص (كلاهما يستخدم `.htaccess` خاص بمجلده فقط).

## البنية العامة

```
/                     نقطة الدخول العامة للموقع (index.php) + .htaccess
/admin/               لوحة التحكم (admin/index.php) + ملفات css/js عامة
/install/             معالج التثبيت (يُقفل تلقائيًا بعد النجاح)
/core/                نواة النظام (لا يُسمح بالوصول المباشر لها عبر المتصفح)
/modules/              الإضافات المستقلة (كل إضافة في مجلدها الخاص)
/themes/default/       القالب العام للموقع (CSS/JS عادي بدون أي أدوات بناء)
/storage/              الرفع، النسخ الاحتياطي، السجلات، التخزين المؤقت (محمية بالكامل من الوصول المباشر عدا uploads)
/config.php            يُنشأ تلقائيًا أثناء التثبيت (غير موجود في المستودع)
```

### Core + Modules

- **النواة (Core)** تشمل فقط: التوجيه، الاتصال بقاعدة البيانات، تسجيل دخول الإدارة، الصلاحيات، الإعدادات العامة، القالب، إدارة الإضافات، مكتبة الوسائط المركزية، القوائم، المدن، الفروع (اختيارية تلقائيًا)، سجل العمليات، النسخ الاحتياطي.
- **كل ميزة أخرى إضافة مستقلة** داخل `/modules/{slug}/` بملف تعريف `module.json`، ملف `Module.php`، وملف `install.sql`. تعطيل أي إضافة لا يؤثر على عمل النواة أو بقية الإضافات (كل استدعاء لإضافة محاط بمعالجة أخطاء لا تُسقط الطلب بالكامل).
- من لوحة التحكم → الإضافات: عرض/تثبيت/تفعيل/تعطيل/رفع ZIP/إزالة (مع خيار الاحتفاظ بالبيانات أو حذفها).

راجع `docs/creating-a-module.md` لشرح تفصيلي لبناء إضافة جديدة، و`docs/permissions.md` لشرح نظام الصلاحيات، و`docs/backup.md` لشرح النسخ الاحتياطي والاستعادة.

## الأمان

- جميع الاستعلامات عبر PDO بمعاملات مجهزة (Prepared Statements) — لا تراكيب SQL يدوية بمدخلات المستخدم.
- تنظيف/تهريب كل مخرج HTML عبر `Security::e()`، وتنظيف مدخلات HTML من لوحة التحكم عبر `Security::cleanHtml()`.
- حماية CSRF على كل نموذج POST (`Csrf::field()` + `Csrf::verifyRequestOrFail()`).
- كلمات مرور الإدارة مشفّرة عبر `password_hash()` (bcrypt/argon حسب إعداد PHP الافتراضي).
- رفع الملفات: التحقق من النوع الحقيقي للصور، قائمة امتدادات مسموحة، حد أقصى للحجم، تعطيل تنفيذ PHP داخل مجلد الرفع (`.htaccess` + `php_flag engine off`).
- عدم عرض أخطاء قاعدة البيانات أو مسارات السيرفر للزوار في بيئة الإنتاج (`APP_DEBUG=false`)؛ كل الأخطاء تُسجَّل في `storage/logs/`.
- بيانات جوال العائلة والقائمة البريدية غير مفهرسة وغير متاحة إلا بصلاحية إدارية مخصصة (`robots.txt` يمنع فهرسة لوحة التحكم والمسارات الحساسة أيضًا).
- لا توجد بيانات دخول ثابتة داخل الكود، ولا مفاتيح سرية داخل المستودع — كل ذلك يُنشأ عشوائيًا أثناء التثبيت داخل `config.php` (غير مرفوع في Git).

## رقم الإصدار

- إصدار النواة الحالي: **1.0.0** (`core/version.php`).
- كل إضافة تحمل رقم إصدارها الخاص داخل `module.json`.

## الترخيص وبيانات الدخول

لا توجد أي بيانات دخول افتراضية مضمّنة في النظام. يتم إنشاء أول حساب مدير حصريًا أثناء معالج التثبيت من البيانات التي تدخلها أنت.
