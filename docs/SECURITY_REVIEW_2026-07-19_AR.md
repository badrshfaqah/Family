# تقرير مراجعة وتقوية الحماية

**المشروع:** نظام إدارة محتوى العوائل والقبائل  
**التاريخ:** 19 يوليو 2026  
**النطاق:** النواة، لوحة التحكم، الوحدات، الرفع، الجلسات، الاستعادة والنسخ الاحتياطي، Push، التثبيت، وإعدادات خادم الويب.

## الملخص التنفيذي

بدأت المراجعة كفحص تشخيصي دون تعديل، وكشفت ثغرتين مرتفعتي الخطورة وعدة نقاط متوسطة ومنخفضة. تم بعد ذلك تنفيذ الإصلاحات، وإضافة طبقات دفاع جديدة، وتحويل الفحوص المهمة إلى اختبارات رجعية تعمل محليًا وفي GitHub Actions.

الحالة الحالية:

- أُغلقت ثغرات Stored XSS وتجاوز Rate Limiting وHost Header Poisoning وPush SSRF وCSV Formula Injection.
- شُددت المصادقة والجلسات واستعادة كلمة المرور وتسجيل الخروج.
- أضيفت مصادقة ثنائية TOTP مع رموز استرداد أحادية الاستخدام.
- أصبحت النسخ الجديدة قابلة للتخزين خارج جذر الموقع ومشفرة بتشفير streaming موثّق السلامة.
- أضيف CSP nonce-based ومنعت معالجات JavaScript المضمنة.
- شُدد رفع الملفات وحزم الإضافات واستعادة SQL.
- أضيف إعداد Nginx مرجعي واختبارات أمنية مستمرة.

## النتائج الأصلية وما تم بشأنها

| الخطورة | النتيجة | المعالجة |
|---|---|---|
| مرتفعة | منقّي HTML بالتعبيرات المنتظمة قابل للتجاوز، والمحتوى يُعرض خامًا | استبداله بمحلل DOM وقائمة سماح للعناصر والسمات والبروتوكولات، مع CSP كدفاع ثانٍ |
| مرتفعة | Rate Limiter يبقى في نافذة منتهية إلى الأبد بعد أول دورة | إعادة تهيئة العداد ووقت النافذة بصورة آمنة للطلبات المتزامنة |
| متوسطة | endpoint اشتراكات Push غير محدود وقابل لإغراق الجدول | CSRF، حد محاولات، تحقق من الأطوال وBase64URL |
| متوسطة | Push endpoint يمكن أن يتحول إلى SSRF وقت إرسال الإدارة | رفض IP الخاص والمحجوز وloopback، منع credentials والمنافذ غير 443، تثبيت DNS عبر cURL، منع redirects |
| متوسطة | رموز استعادة كلمة المرور مخزنة صريحة ولا تبطل الجلسات | تخزين SHA-256، إبطال الرموز السابقة، وبصمة كلمة المرور داخل الجلسة لإبطال كل الجلسات بعد التغيير |
| منخفضة | تسجيل الخروج عبر GET | تحويله إلى POST محمي بـCSRF |
| متوسطة | بناء الروابط المطلقة من Host القادم من العميل | `APP_URL` موثوق وfallback إلى `SERVER_NAME` مع تحقق صارم |
| متوسطة | ملفات الرفع تُتحقق غالبًا بالامتداد فقط | فحص MIME والتوقيع الفعلي للصور، ومنع الامتدادات النشطة دائمًا |
| متوسطة | استخراج ZIP مباشرة دون حدود أو تحقق شامل | منع traversal والمسارات المطلقة والروابط الرمزية، وحد 20MB مضغوط و100MB مستخرج و2000 عنصر |
| متوسطة | استعادة SQL تقبل أي أوامر داخل الملف | قائمة سماح لأوامر النسخة المولدة وجداول بادئة النظام، وحد رفع وفحص أخطاء النقل |
| متوسطة | CSV قد ينفذ صيغًا عند فتحه في Excel | تعقيم كل خلية تبدأ بمؤشرات الصيغ بعد whitespace |
| تقوية | غياب CSP/HSTS/Permissions-Policy | إضافة CSP nonce-based وHSTS عند HTTPS وPermissions-Policy |

## تفاصيل التنفيذ

### 1. المصادقة والجلسات

- تجديد Session ID عند الدخول وعند الانتقال إلى تحدي 2FA.
- تفعيل `session.use_strict_mode` و`session.use_only_cookies` وHttpOnly وSameSite=Lax.
- اشتقاق Secure cookie من `APP_URL` حتى خلف reverse proxy.
- بصمة HMAC من password hash داخل الجلسة؛ تغيير كلمة المرور يبطل الجلسات السابقة.
- تحقق مكلف بكلمة مرور وهمية للحساب غير الموجود لمنع تعداد الحسابات بفارق التوقيت.
- إعادة تشفير كلمات المرور تلقائيًا عند نجاح الدخول إذا تغيرت خوارزمية PHP الافتراضية.
- حدود دخول مستقلة للحساب ولعنوان IP، بدل مفتاح مركب يمكن تجاوزه بتوزيع الهجوم.
- حد مستقل لطلبات نسيان كلمة المرور حسب البريد وعنوان IP.

الملفات الرئيسية: `core/Auth.php`, `core/Support/Session.php`, `core/Support/RateLimiter.php`.

### 2. المصادقة الثنائية 2FA

- دعم TOTP القياسي: SHA-1، ستة أرقام، 30 ثانية، ونافذة ±30 ثانية.
- مفتاح 160-bit Base32 متوافق مع تطبيقات Authenticator.
- تشفير المفتاح في قاعدة البيانات بـAES-256-GCM ومفتاح مشتق من `SECURE_AUTH_KEY`.
- ثمانية رموز استرداد عشوائية، مخزنة بـ`password_hash`، وكل رمز يُحذف بعد أول استخدام.
- تحدي دخول منفصل صالح لخمس دقائق ومحدود المحاولات.
- واجهة تفعيل وتعطيل داخل رابط «الأمان» في لوحة التحكم.
- جدول `admin_user_mfa` موجود في schema ويُنشأ تلقائيًا للتثبيتات الحالية.

الملفات الرئيسية: `core/TwoFactor.php`, `core/Admin/Controllers/TwoFactorController.php`, `core/Admin/Views/security/two-factor.php`.

### 3. XSS وحماية المتصفح

- قائمة سماح لعناصر التنسيق الشائعة فقط.
- إزالة العناصر غير المسموحة مع محتواها، وإزالة السمات غير المعروفة.
- السماح فقط بـHTTP/HTTPS للصور، وإضافة mailto/tel للروابط.
- فرض `noopener noreferrer` على الروابط ذات `_blank`.
- CSP تمنع السكربتات دون nonce وobject/frame/base غير المسموح.
- نقل `onclick` و`onchange` إلى listeners في ملفات JavaScript الخارجية.
- إضافة HSTS وPermissions-Policy وnosniff وframe protection وReferrer-Policy.

الملف الرئيسي: `core/Support/Security.php`.

### 4. رفع الملفات والإضافات

- حظر PHP وHTML وSVG وXML وJavaScript وامتدادات التنفيذ حتى لو أضافها المدير في الإعدادات.
- فحص `getimagesize` وMIME الفعلي لكل صورة بما فيها WebP.
- خرائط MIME لوثائق Office وPDF والصوت والفيديو.
- حظر المحتوى النشط القديم داخل `storage/uploads` في Apache وإعداد Nginx المرجعي.
- رفع الإضافات معطل افتراضيًا عبر `ALLOW_MODULE_UPLOAD=false`.
- عند تفعيله مؤقتًا: حدود الحجم والعدد، ومنع traversal وsymlink وZip bombs.

ملاحظة: الإضافة الموثوقة تظل كود PHP كامل الصلاحيات بطبيعتها؛ لا توجد sandbox آمنة لكود PHP داخل العملية نفسها.

### 5. النسخ الاحتياطية والاستعادة

- `BACKUP_PATH` يسمح بوضع النسخ خارج `public_html`.
- `BACKUP_ENCRYPTION_KEY` يشفر النسخ الجديدة بصيغة `.enc` باستخدام Sodium secretstream XChaCha20-Poly1305.
- التشفير streaming بقطع 1MB، مع tag نهائي لكشف القطع أو العبث.
- الملفات المشفرة بصلاحية 0600 والمجلد بصلاحية 0700.
- تدعم الاستعادة ملف SQL أو نسخة قاعدة بيانات `.enc` من نفس مفتاح التشفير.
- قائمة أوامر SQL المسموحة: foreign key checks وDROP TABLE وCREATE TABLE وINSERT INTO لجداول النظام فقط.
- النسخ القديمة غير المشفرة تبقى قابلة للتنزيل ولا تُحوّل تلقائيًا.

تحذير تشغيلي: يجب حفظ `BACKUP_ENCRYPTION_KEY` في مدير أسرار منفصل؛ فقدانه يجعل النسخ المشفرة غير قابلة للاستعادة.

### 6. Push والبريد والتصدير

- Push subscription محمي بـCSRF وRate Limit والتحقق البنيوي.
- endpoint يجب أن يكون HTTPS عام على 443 دون userinfo.
- DNS يُحل ويُثبت في cURL لمنع DNS rebinding.
- لا redirects ولا بروتوكول غير HTTPS.
- عناوين البريد تتحقق بـ`FILTER_VALIDATE_EMAIL` قبل بناء الترويسات أو SMTP commands.
- EHLO وFrom لم يعودا يستخدمان `HTTP_HOST` الخام.
- تصدير Directory وNewsletter يستخدم طبقة CSV مشتركة تمنع صيغ Excel.

### 7. خادم الويب والتثبيت

- أضيف `APP_URL`, `BACKUP_PATH`, `BACKUP_ENCRYPTION_KEY`, و`ALLOW_MODULE_UPLOAD` إلى التثبيت وملف العينة.
- متطلبات التثبيت تشمل DOM وOpenSSL وSodium.
- Apache يمنع المحتوى النشط داخل uploads.
- مثال Nginx يمنع PHP خارج نقاط الدخول، يحجب storage/config/dotfiles، ويمنع تنفيذ أو تقديم المحتوى النشط المرفوع.
- عولج تحذير PHP 8.5 الخاص بـPDO MySQL init attribute مع الحفاظ على توافق PHP 8.1.

راجع: `docs/nginx-security.conf.example`.

## الاختبارات المنفذة

### اختبارات آلية

الملف `tests/security_regressions.php` يغطي:

- حمولات XSS: iframe/srcdoc وSVG وjavascript URL وevent handlers.
- ثبات CSP nonce.
- CSV formula injection.
- متجه RFC معروف لـTOTP.
- Host header poisoning.
- ملف WebP مزيف.
- أوامر استعادة SQL المسموحة والممنوعة.
- Push SSRF إلى loopback وmetadata IP.
- ZIP traversal عند توفر ZipArchive.
- دورة تشفير وفك تشفير نسخة أكبر من 1MB.
- عدم وجود inline event handlers أو inline scripts بلا nonce.

كما أضيف workflow في `.github/workflows/security.yml` لفحص:

- صياغة كل ملفات PHP.
- صياغة JavaScript.
- جميع اختبارات الحماية السابقة عند push وpull request.

### اختبار تكاملي فعلي بالمتصفح

أُنشئت بيئة مؤقتة بالكامل ثم حُذفت بعد الاختبار:

1. MySQL 9.7.1 محلي مؤقت.
2. PHP 8.5.7 development server.
3. المرور بكل خطوات معالج التثبيت.
4. إنشاء حساب مدير وتسجيل الدخول.
5. فتح واجهة الأمان وتفعيل TOTP برمز فعلي.
6. التأكد من ظهور رموز الاسترداد مرة واحدة.
7. تسجيل الخروج ثم التأكد من فرض صفحة تحدي 2FA بعد كلمة المرور.
8. الدخول برمز استرداد.
9. إعادة استخدام الرمز نفسه والتأكد من رفضه.
10. إنشاء نسخة قاعدة بيانات مشفرة خارج جذر المشروع والتأكد أن الملف `data` وليس SQL صريحًا وصلاحيته 0600.
11. فحص رؤوس CSP وPermissions-Policy وnosniff وframe/referrer headers.
12. فحص Console: لا أخطاء ولا تحذيرات في التدفقات المختبرة.

## تعليمات نشر التغييرات

أضف إلى `config.php` في التثبيتات الحالية:

```php
define('APP_URL', 'https://family.example.com');
define('BACKUP_PATH', '/srv/private-backups/family-cms');
define('BACKUP_ENCRYPTION_KEY', '64_OR_MORE_RANDOM_CHARACTERS');
define('ALLOW_MODULE_UPLOAD', false);
```

ثم:

1. تأكد من توفر PHP extensions: `dom`, `openssl`, `sodium`, `fileinfo`, `pdo_mysql`.
2. أنشئ `BACKUP_PATH` خارج document root بملكية مستخدم PHP وصلاحية 0700.
3. خزّن نسخة آمنة منفصلة من `BACKUP_ENCRYPTION_KEY`.
4. طبّق إعداد Apache الحالي أو عدّل مثال Nginx حسب مسار التركيب وPHP-FPM socket.
5. اختبر روابط الموقع والبريد بعد ضبط `APP_URL`.
6. اطلب من المدراء تفعيل 2FA وحفظ رموز الاسترداد خارج الموقع.
7. راجع النسخ القديمة غير المشفرة وانقلها إلى تخزين مشفر أو احذفها وفق سياسة الاحتفاظ.
8. شغّل `php tests/security_regressions.php` قبل النشر.

## آثار متوقعة وتوافق

- الجلسات الإدارية الموجودة قبل النشر ستتطلب تسجيل دخول جديد مرة واحدة.
- روابط الاستعادة القديمة الصريحة تظل متوافقة حتى انتهاء صلاحيتها؛ الروابط الجديدة مخزنة كـhash.
- رفع الإضافات سيتوقف افتراضيًا حتى تفعيل العلم صراحة.
- النسخ الجديدة ستكون `.enc` عند ضبط مفتاح التشفير.
- CSP قد يمنع أي تكامل خارجي جديد حتى إضافته بوضوح إلى السياسة.
- إذا لم يملك مستخدم MySQL صلاحية CREATE TABLE، يجب إنشاء جدول `admin_user_mfa` من schema أثناء النشر.

## المخاطر المتبقية والقرارات المطلوبة

1. **2FA اختياري لكل مدير:** التقنية مكتملة، لكن فرضها تنظيميًا على كل المدراء يحتاج قرار الفريق.
2. **الإضافات:** عند تفعيل رفع الإضافات، يجب اعتبار كل ZIP كودًا كامل الثقة ومراجعته أو توقيعه خارج النظام.
3. **النسخ القديمة:** لا تُعاد كتابتها أو تشفيرها تلقائيًا لتجنب تدمير نسخة قد تكون الوحيدة.
4. **CSP:** السياسة قوية، وأي خدمة خارجية جديدة تحتاج تحديثًا مقصودًا.
5. **مراقبة الإنتاج:** يلزم ربط السجلات بتنبيهات فعلية وسياسة تدوير واحتفاظ حسب بيئة الاستضافة.
6. **اختبار الاستعادة الدوري:** نجاح إنشاء النسخة لا يغني عن تجربة استعادة مجدولة على بيئة معزولة.

## حالة التسليم

- التغييرات منفذة محليًا ومختبرة.
- لم تُنشأ commit أو push ضمن هذه الجلسة.
- لا توجد بيانات أو خوادم اختبار متبقية بعد التنظيف.
